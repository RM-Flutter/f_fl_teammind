شاشة More features/more/more_screen.dart

اللي لقيته في الكود

أساسي مسافة فاضية كبيرة بين المسمى الوظيفي وأول عنصر القائمة بتبدأ بعد SizedBox(height: height * 0.14) ثابتة (سطر 132). الهيدر 0.25 والصورة متحطوطة عند 0.15، فكل الحسابات نسبة من طول الشاشة. على الشاشات الطويلة بتطلع مسافة فاضية، وعلى القصيرة الاسم ممكن يركب على أول عنصر.
أساسي عنوان القسم بعيد عن عناصره بنفس بُعده عن القسم اللي قبله كل عنوان قسم (MY WORK، MY ACCOUNT …) قبله SizedBox(15) وبعده SizedBox(15) (سطور 149–164 و219–234 و…). المفروض العنوان يبقى لازق في عناصره: AppSpacing.section فوقه وsectionHeaderGap تحته.
أساسي الصفوف طويلة والفواصل تقيلة DefaultListTile (سطر 865): ‏ListTile عادي (56) وفوقه vertical: xs، فالصف بيوصل لحوالي 64. والـ Divider سُمكه 2 ولونه ثابت 0xFFF3F3F3 ومن الحافة للحافة.
شكل كل النصوص Capital عناوين العناصر toUpperCase() بحجم 12 وعناوين الأقسام كمان Capital بحجم 13، فالمستويين شبه بعض ومفيش فرق واضح بينهم. وفي العربي toUpperCase مالهاش أي تأثير.
سلوك عنوان القسم بيظهر حتى لو القسم فاضي عنوان MY REQUESTS (سطر 221) بيظهر حتى لو باكدج emp-requests مش موجودة، فبيطلع عنوان مفيش تحته حاجة. ونفس الكلام ممكن يحصل في أقسام تانية.
نظافة كود العنوان متكرر 7 مرات بلوك Padding → Container(alignment) → Text متكرر 7 مرات بنفس الشكل. المفروض يبقى widget واحد، وكمان Alignment اليدوي مش محتاجينه لأن AlignmentDirectional بيتعامل مع RTL لوحده.

الخطوات

  1. widget واحد لعنوان القسم.

    في نفس الملف (زي DefaultListTile) أعمل _MoreSectionLabel(title) وفيه: padding: EdgeInsetsDirectional.fromSTEB(page, section, page, sectionHeaderGap)، وحجم 12، وw700، وletterSpacing: .6، بلون AppColors.buttons. وأشيل كل الـ SizedBox(15) اللي حوالين العناوين.

  2. العنوان يظهر بس لو تحته عناصر.

    كل قسم أجمّع عناصره في List<Widget>، ولو القايمة فاضية مش هرسم العنوان. وده كمان هيصلح عنوان MY REQUESTS اللي بيظهر من غير باكدج.

  3. صف أخف.

    DefaultListTile: ‏minVerticalPadding: 0 وvisualDensity: compact علشان الصف يبقى حوالي 52، وminLeadingWidth: 24، والأيقونة جوه مربع 32×32 بخلفية buttons شفافة 10% زي أيقونات كروت الهوم. والعنوان بحجم 14 وw500 من غير toUpperCase.

  4. فاصل رفيع يبدأ من بداية النص.

    Divider(height: 1, thickness: 1) بلون من الثيم (AppColors مش رقم ثابت)، وindent يبدأ من بداية النص، وآخر عنصر في القسم ملوش فاصل.

  5. الهيدر يتحسب من المقاسات الحقيقية مش من نسبة الشاشة.

    أشيل الـ Stack/Positioned المبني على النسب. الهيدر الكحلي يبقى ارتفاعه ثابت (مثلاً 180 + safe area)، والصورة 96 بتتداخل بنصها مع الكارت الأبيض، والاسم والمسمى الوظيفي جوه الـ ListView نفسها كأول عنصر. كده مفيش مسافة متحسبة يدوي، وكمان الاسم والصورة هيعملوا scroll مع القائمة.

  6. Tokens بدل الأرقام.

    ارتفاع الهيدر ومقاس الصورة يتحطوا في AppSizes مش أرقام جوه الشاشة (قاعدة CLAUDE.md). وأحدّث features/more/README.md.

هنعتبره خلص لما

  • المسافة بين المسمى الوظيفي وأول عنصر تبقى زي ما هي (حوالي 24) على iPhone SE وعلى Pro Max.
  • كل عنوان قسم يبعد 8 عن عناصره و16 عن القسم اللي قبله.
  • مفيش عنوان قسم فاضي، وأجرّب ده بحساب ناقصه باكدج.
  • الشاشة تتشاف صح في العربي (RTL) والإنجليزي.

Load More على مستوى الأبلكيشن core + 14 شاشة

ليه الزرار بيظهر وهو مش المفروض يظهر؟

في الإشعارات حجم الصفحة itemsCount = 9. الصفحة الأولى جابت 3 إشعارات بس، يعني أقل من 9، وده معناه إن مفيش غيرهم. بس الكود مش بيقفل hasMoreNotifications غير لما صفحة كاملة ترجع فاضية:

if (newNotifications.isNotEmpty) {
  notifications.addAll(newNotifications);
  if (hasMore) currentPage++;          // hasMore always true
} else {
  hasMoreNotifications = false;        // only flips on an EMPTY page
}
صفحة 1 → 3 عناصر3 أقل من 9، يعني مفيش غيرهم
الكود الحالي: الزرار ظاهربيستنى صفحة فاضية علشان يعرف
بعد التعديل: الزرار مخفي3 < 9 ⇒ hasMore = false

يعني المستخدم بيدوس الزرار، بيروح request كامل للسيرفر، يرجع فاضي، وساعتها بس الزرار يختفي. وكمان hasMoreNotifications مش بيرجع true لما تغيّر بين All وMy Department أو تعمل refresh، فلو قفل مرة مش هيفتح تاني.

ونفس الغلطة موجودة في معظم الشاشات اللي فيها infinite scroll، بس هناك مش باينة لأن مفيش زرار. اللي بيحصل إن فيه request زيادة على الفاضي في آخر كل قائمة.

الحل: قاعدة واحدة في core وكل الشاشات تستخدمها

  1. PaginationState في core/models/pagination_state.dart.

    كلاس صغير بيحفظ page وhasMore وisLoadingMore، وفيه دالة واحدة بتقرر هل فيه صفحة كمان ولا لأ:

    void onPageLoaded({required int received, required int pageSize, Map? meta}) {
  final last = meta?['last_page'] ?? meta?['lastPage'];
  final total = meta?['total'];
  if (last is int)       hasMore = page < last;          // 1) server says
  else if (total is int) hasMore = loadedCount < total;  // 2) server total
  else                   hasMore = received >= pageSize; // 3) short page = end
  if (hasMore) page++;
}
void reset() { page = 1; hasMore = true; isLoadingMore = false; }

    لو السيرفر بيرجع meta فهو اللي يحدد، ولو لأ بنعتمد على إن الصفحة الناقصة يعني إن القائمة خلصت. ودي نفس طريقة Commissions اللي شغالة صح.

  2. AppLoadMoreButton في core/widgets/app_load_more_button.widget.dart.

    بياخد state وitemCount وonPressed. وبيظهر بس لو hasMore && itemCount > 0 && !isLoading، وأثناء التحميل بيظهر loader صغير مكانه، فالمستخدم مش هيشوف الزرار واللودر مع بعض. وده بدل نسختين الزرار المتكررين في Notifications وTasks.

  3. الرجوع للصفحة الأولى عند أي تغيير.

    أي refresh أو filter أو toggle (All/My Department، أو تغيير تاريخ في Tasks) لازم ينادي reset() قبل ما يجيب الصفحة الأولى. ده هيصلح إن الإشعارات بتفضل مقفولة بعد ما تغيّر الـ toggle.

  4. infinite scroll بنفس القاعدة.

    الـ scroll listener بيشيّك على state.hasMore && !state.isLoadingMore، فالـ request الفاضي اللي بيروح في آخر كل قائمة هيختفي في كل الشاشات.

  5. نطبّق على الشاشات واحدة واحدة.

    نبدأ بـ Notifications وTasks لأنهم الاتنين اللي فيهم زرار ظاهر، وبعدهم Requests، وبعدها الباقي بالترتيب اللي في الجدول. كل كنترولر يحتفظ بأسماء متغيراته القديمة، ونخلّي hasMoreNotifications مثلاً يقرأ من state.hasMore، علشان منكسرش أي حاجة بتستخدمه.

  6. Docs.

    أضيف قاعدة pagination لقواعد app_design.dart وcore/widgets/README.md وcore/models/README.md، وأحدّث README كل feature أعدّل فيها.

محتاج منك إجابة

  • API الإشعارات (/emp_requests/v1/notifications/list) بيرجع meta أو total؟ لو آه، الزرار هيبقى دقيق حتى لو آخر صفحة جت كاملة بالظبط (9 من 9). لو لأ، في الحالة دي بس المستخدم هيدوس الزرار مرة زيادة ترجع فاضية.
  • الإشعارات تفضل بزرار ولا تبقى infinite scroll زي باقي الأبلكيشن؟ حالياً الاتنين شغالين مع بعض.

هنعتبره خلص لما

  • حساب عنده 3 إشعارات: الزرار مايظهرش خالص.
  • حساب عنده 20 إشعار: الزرار يظهر مرتين، وبعد الصفحة التالتة (2 عنصر) يختفي.
  • لما أغيّر All ↔ My Department الزرار يرجع يظهر لو القسم التاني فيه أكتر من صفحة.
  • في الشاشات اللي فيها scroll، مفيش request على صفحة فاضية في الـ Dio log لما توصل لآخر القائمة.
